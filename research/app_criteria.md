## 2. 앱들의 공통 패턴

### 거의 모든 앱이 쓰는 것
1. **목표 선택**: Freeletics, Leap, Madbarz, Sworkit, Seven, Fitbod, 플랜핏, 콰트, BetterMe. 감량, 근력·근육, 체력 유지 같은 2–4개 선택지가 일반적입니다.
2. **체력 수준(초·중·고)**: 자가 선택(Madbarz, Seven, NTC, Leap)이거나 경험 질문(Fitbod, 플랜핏, Sworkit "얼마나 자주 운동하나")으로 받습니다.
3. **장비 유무, 운동 시간, 주당 일수**: Freeletics(2–5일, 장비 토글), Fitbod(시간→운동 개수), NTC(시간 필터), 플랜핏(보유 기구).
4. **운동 태그 기반 필터링**: 수준, 부위, 장비, 충격 태그를 붙여 두고 걸러 냅니다(Sworkit 필터, NTC 태그, Freeletics 제외 규칙).

### 일부 앱만 쓰는 것
- **실제 체력 테스트**: Sworkit(최대 반복 푸시업·스쿼트, 저충격 버전 별도)과 Freeletics(평가 주)뿐입니다. J&J는 "초기 체력 수준을 가늠한다"고만 밝히고 방식은 공개하지 않습니다.
- **운동 후 피드백으로 자동 조정**: Freeletics(자세 평가·기록 시간), Seven("Too Hard"→다음 주 쉽게), Leap("Too hard/easy?", 리뷰 기준), NTC 2016판(난이도 평가), Fitbod·플랜핏(수행 기록). Madbarz·콰트·BetterMe는 고정 플랜에 가깝습니다.
- **저충격·소음 옵션**: Freeletics(quiet mode, 달리기 제외, 좁은 공간)와 Sworkit(충격 Low/Normal/High, Quiet, 저충격 평가)이 명시적입니다. BetterMe는 저충격 프로그램을 따로 둡니다. NTC·Seven·Madbarz·콰트에서는 확인하지 못했습니다.
- **부상·불편 부위 제외**: Freeletics(근육통 부위, 운동 제외), Leap(부상 질문→피할 운동 표시), 플랜핏(부상 질문, 리뷰 기준).

### 실제 앱이 BMI로 운동을 고르는가?
**대부분 그렇지 않습니다. BMI로 운동 종목을 직접 바꾼다고 공식 문서에 밝힌 앱은 이번 조사에서 하나도 찾지 못했습니다.**
- **Freeletics**만 공식 블로그에서 "체중과 BMI로 개인 체력 수준을 분류한다"고 씁니다. 다만 BMI는 기록 시간, 자세 피드백, 제한 부위와 함께 들어가는 **여러 입력 중 하나**이고, 체력 수준을 분류하는 데 씁니다. "BMI ≥ X면 Y 운동 제외" 같은 규칙은 공개된 적이 없습니다. 운동 수행 기록 같은 실제 성과 데이터가 함께 쓰인다는 점이 핵심입니다.
- **Freeletics(헬프센터 발췌)**는 저니 추천에 나이, 체중, 키를 쓴다고 합니다. **BetterMe**도 퀴즈에서 BMI를 쓴다는 리뷰가 있습니다. 둘 다 계산 방식은 공개하지 않습니다.
- **Fitbod**는 키·체중·나이를 프로필에 두지만, 공식 설명상 칼로리 추정용입니다.
- 점프 제외는 BMI가 아니라 **사용자가 켜는 옵션**(Freeletics quiet mode, Sworkit 충격 필터)으로 처리하는 게 일반적입니다.
- 근거 문헌 쪽에서는 Klika & Jordan(2013)이 "과체중·비만, 운동을 쉬던 사람, 부상 이력자, 고령자"에게 주의를 권합니다(2차 출처 인용). ACSM 비만 자료도 "start low and go slow"(낮게 시작해 천천히 올리기)를 권합니다[공식-발췌]. 즉 **"체중이 많이 나가면 낮은 강도·저충격으로 시작"하라는 근거는 있지만, 이것은 시작 강도와 기본 설정의 문제이지 BMI 컷오프로 운동 목록을 가르라는 뜻은 아닙니다.**

→ 결론: 홈핏 메이트의 "BMI ≥ 25면 점프 제외" 규칙은 실제 앱에서 같은 사례를 찾을 수 없습니다. 실제 앱들은 (a) 사용자가 선택하는 저충격·조용히 옵션과 (b) 체력 테스트나 운동 후 피드백 같은 **수행 데이터**로 루틴을 바꿉니다. BMI는 기본값을 정하는 참고 신호 정도로 낮추는 편이 근거에 맞습니다.

### 3-2. 초기 단계 결정 규칙 (스케치)

```python
# 각 테스트를 0/1/2점으로 환산 (기준값은 팀 조정용 임시값, 아래 '확인 못 한 것' 참고)
def score_pushup(n, knee):           # knee=True면 무릎 푸시업
    if knee: n = n * 0.6              # 무릎 푸시업은 가중치를 낮춤 (임시값)
    return 0 if n < 8 else 1 if n < 20 else 2
def score_squat30(n):  return 0 if n < 12 else 1 if n < 20 else 2
def score_plank(sec):  return 0 if sec < 30 else 1 if sec < 60 else 2

total = score_pushup(p, knee) + score_squat30(s) + score_plank(t)   # 0~6
test_level = 1 if total <= 2 else 2 if total <= 4 else 3            # 1=초급 2=중급 3=고급

level = min(test_level, self_level)   # 자가 선택보다 테스트가 낮으면 테스트를 따름(안전 쪽)
if bmi >= 30 and level > 1:
    level -= 1                         # 시작만 한 단계 낮춤. 진행 규칙으로 금방 회복 가능
```
- 테스트를 건너뛰면 자가 선택 수준을 그대로 씁니다(Madbarz·Seven 방식).
- 부위별 점수를 따로 저장해 두면(예: 상체 0점, 하체 2점) 푸시업 변형은 쉬운 것, 스쿼트 변형은 어려운 것을 고를 수 있습니다. "BMI <25면 모두 같은 루틴" 문제가 여기서 풀립니다.

### 3-3. 운동 선택 규칙 (JSON 데이터 구조)

```json
{"id": "jump_squat", "name": "점프 스쿼트", "pattern": "squat", "level": 3,
 "impact": "high", "joints": ["knee"], "easier": "squat", "harder": null,
 "reps": 12, "sec": null}
```
- 패턴(push / squat / lunge / hinge / core / cardio)마다 사용자 단계에 맞는 변형을 하나씩 고르고, **상체→하체→코어 순서로 번갈아** 배치합니다(Klika & Jordan 원칙).
- 걸러내는 순서: 저충격 ON이면 `impact=="high"` 제외 → 불편 부위면 해당 `joints` 제외 → 남은 것 중 `level`에 맞는 것. 맞는 게 없으면 `easier` 체인을 따라 내려갑니다.
- 목표별 구성: 감량은 서킷 형태(30–40초 운동/10–20초 휴식, 2–3바퀴, cardio 비중↑). 근력·근지구력은 세트 형태(3세트, 목표 반복 8–15회, 휴식 60–90초). 유지는 그 중간입니다. ACSM 2009는 초보자에게 8–12RM, 주 2–3회를 권합니다.

### 3-4. 진행 규칙 (운동 후 피드백 3버튼 + 완료 여부)

| 운동 후 입력 | 규칙 | 근거 |
|---|---|---|
| "쉬웠어요" + 전부 완료, **2회 연속** | 반복 수·시간 **+10%**(최소 +1회/+5초) | ACSM 2009: 목표보다 1–2회 더 하는 상태가 **연속 2회**면 부하를 2–10% 올림[공식, 원문 확인]. Freeletics 별(전 동작 excellent)→더 어려운 운동[공식] |
| 배율이 1.3배에 도달 | 배율을 1.0으로 되돌리고 **한 단계 어려운 변형으로 교체**(`harder`, 예: 무릎 푸시업→푸시업) | Seven: 스쿼트→파이크 스쿼트처럼 동작 교체로 진행[공식], Freeletics 더 어려운 운동 배정[공식] |
| "적당했어요" | 유지 | — |
| "힘들었어요" 또는 미완료 | 다음 세션 **−10%** | Seven "Too Hard"→다음에 쉽게[공식-발췌], Leap "Too hard/easy?"[리뷰] |
| "힘들었어요" **2회 연속** | 한 단계 쉬운 변형으로 교체(`easier`) | 같은 근거 |
| 4주마다 | 체력 테스트 다시 하기 → 단계 재계산, 결과 그래프 표시 | Freeletics 저니마다 평가 주[공식/포럼], Sworkit 기준선 추적[공식-발췌] |

- 저장: `data/users/<id>.json`에 `{level, multiplier, streak_easy, streak_hard, history:[...]}` 형태로 두면 DB 없이 구현할 수 있습니다.
- 이 진행 로직은 팀이 직접 설계한 핵심 로직으로 설명하기 좋고, 단위 테스트 몇 개로 검증할 수 있습니다.

## 4. 확인 못 한 것

- **Freeletics**: 헬프센터(help.freeletics.com)가 403으로 막혀 공식 포럼 사본과 검색 발췌로 대신했습니다. "체중·BMI로 체력 분류" 문장이 현재 버전에도 적용되는지, BMI가 계산에서 얼마나 비중을 갖는지는 공개된 자료가 없습니다. 온보딩에서 푸시업 개수를 묻는지도 확인하지 못했습니다.
- **J&J 7 Minute Workout**: Smart Workout이 묻는 질문과 강도를 올리는 규칙은 공개 자료에서 찾지 못했습니다. 보도자료는 2014년, 앱스토어 설명은 2021–2022년 기준입니다.
- **Klika & Jordan 2013 원문**: 유료라 열람하지 못했습니다. 과체중 주의 문구, 등척성 동작 주의, 8/10 강도는 원문을 인용한 2차 출처(BU Wellness, Sports Med Today, 각종 요약)에서 가져왔습니다.
- **Leap Fitness**: "Too hard/easy?" 조정과 부상 질문은 제3자 온보딩 분석(screensdesign)에만 나옵니다. 공식 설명이나 헬프센터에서는 확인하지 못했고, Google Play 페이지는 직접 열리지 않았습니다.
- **Seven**: "Too Hard → 다음 주 쉽게"는 검색 결과에 나온 앱스토어 개발자 답변 발췌입니다. 직접 연 앱스토어 페이지에는 그 문장이 없었고, 헬프센터는 403이었습니다. 저충격 옵션 유무도 확인하지 못했습니다.
- **Sworkit**: 헬프센터 인증서가 만료되어 열리지 않아 발췌문만 확인했습니다. 체력 평가의 정확한 종목, 시간, 결과로 수준을 정하는 규칙은 확인하지 못했습니다.
- **Nike Training Club**: 현재 온보딩 질문과 자동 조정 여부는 공식 자료가 없습니다(리뷰와 2016년 기사뿐). 앱 내 저충격·강도 필터도 확인하지 못했습니다.
- **Fitbod**: 헬프센터가 403이라 발췌만 확인했습니다. 성별·나이·체중이 시작 무게에 반영되는지는 공식 설명이 없습니다.
- **한국 앱**: 플랜핏의 정확한 온보딩 항목(성별·나이·키·체중 포함 여부)과 콰트의 맞춤 추천 로직은 확인하지 못했습니다. 층간소음·점프 없음 모드를 공식 기능으로 둔 국내 앱도 찾지 못했습니다(관련 블로그·기사는 운동법 소개뿐). 다노 등 다른 국내 앱은 조사하지 못했습니다.
- **테스트 기준값**: 3-2의 푸시업·스쿼트·플랭크 점수 기준은 **임시값**입니다. ACSM이나 CSEP의 연령·성별 푸시업 규준표, 국민체력100 등급 기준표를 직접 확인하지 못했습니다. 발표 전에 국민체력100(nfa.kspo.or.kr) 기준표나 ACSM 지침서의 규준표로 보정하고 출처를 적는 것을 권합니다.
- **ACSM 비만 운동 자료**: "start low and go slow" 문구는 검색 발췌로만 확인했습니다(PDF 403).
- 앱 설치, 로그인, 실제 온보딩 체험은 하지 않았습니다. 모든 내용은 공개 웹 자료 기준입니다.
